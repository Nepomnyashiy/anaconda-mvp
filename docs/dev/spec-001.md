# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)

**Проект:** Корпоративная платформа «Anaconda»  
**Модуль:** Единое окно продаж (Unified Sales Core) + CRM Lite  
**Версия:** 0.7 (M-Sport Edition)  
**Дата:** 02.02.2026

---

## 1. Введение и Цели

Разработка MVP десктоп-ориентированного веб-приложения для агрегации входящих коммуникаций.

**Основная цель:** Реализация принципа «Одного окна», объединяющего Telegram и Email в единую ленту с возможностью идентификации клиента.

**Стиль:** Строгий корпоративный дизайн на основе палитры BMW M-Motorsport.

---

## 2. Стек технологий

Согласно архитектурному стандарту проекта:

- **Backend:** Python 3.11 + FastAPI (Asynchronous)
- **Database:** SQLite (для MVP) → миграция на PostgreSQL 16
- **ORM:** SQLAlchemy (Async)
- **Frontend:** Vue.js 3 (Composition API) + Tailwind CSS
- **Protocol:** REST API + Long Polling (для обновления интерфейса)

## 4. Архитектура Базы Данных

Реализовать схему "Звезда", где центром является Контакт.

### 4.1. ER-Диаграмма (Сущности)

**organizations**
- `id` (PK) - Primary Key
- `name` (String) - Название организации
- `is_vip` (Boolean) - VIP-статус

*Назначение: Хранение юрлиц (аналог Контрагентов в ERP).*

**contacts**
- `id` (PK) - Primary Key
- `name` (String) - ФИО
- `position` (String) - Должность
- `org_id` (FK → organizations) - Ссылка на организацию
- `email` (Index, Unique) - для матчинга почты
- `telegram_id` (Index, Unique) - для матчинга Telegram

**messages**
- `id` (PK) - Primary Key
- `text` (Text) - Тело сообщения
- `created_at` (Timestamp) - Дата создания
- `source` (Enum: 'email', 'telegram') - Источник сообщения
- `sender_id` (String) - "Сырой" идентификатор (email или chat_id)
- `is_read` (Boolean) - Флаг прочитанности

## 5. Функциональные требования (Backend)

### 5.1. Агрегатор сообщений (Worker)

Реализовать фоновый процесс (asyncio), запускающийся при старте приложения (`@app.on_event("startup")`).

**Частота опроса:** Каждые 3-5 секунд

**Источники:**

1. **Telegram Bot API:** 
   - Метод `getUpdates`
   - Обрабатывать `message`
   - Игнорировать `edited_message`

2. **IMAP (Email):** 
   - Подключение к `imap.yandex.ru` (SSL)
   - Забирать только непрочитанные (UNSEEN) или последние N сообщений
   - Парсить тело письма, очищая от лишних HTML-тегов

**Сохранение:** Все входящие события записывать в таблицу `messages`.

### 5.2. Логика идентификации (CRM Core)

При запросе списка чатов (`GET /api/chats`) backend должен выполнять обогащение данных:

1. Берет уникальные `sender_id`
2. Ищет совпадение в таблице `contacts` (по полю `email` ИЛИ `telegram_id`)
3. Если найден: Возвращает объект контакта + данные организации + флаг `is_known = True`
4. Если не найден: Возвращает `is_known = False`

### 5.3. API Endpoints

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/chats` | Список сгруппированных диалогов (сортировка: новые сверху) |
| GET | `/api/messages/{sender_id}` | История переписки |
| POST | `/api/contacts` | Создание контакта. Принимает `{sender_id, name, position, org_id}`. Автоматически определяет, куда записать sender_id (в email или tg) на основе источника чата |

## 6. Функциональные требования (Frontend)

### 6.1. Layout (Master-Detail)

Экран разделен на две части:

- **Sidebar (30%):** Лента входящих
- **Main (70%):** Активный чат

### 6.2. Поведение "Header" (Активного чата)

Содержимое заголовка зависит от статуса `is_known`:

**Сценарий А: Неизвестный контакт**
- Цвет индикации: Красный (`text-red-600`)
- Текст: "Неизвестный контакт"
- Кнопка действия: `[СОЗДАТЬ]` (Красная, стиль M-Red)
  - Открывает модалку

**Сценарий Б: Известный контакт**
- Цвет индикации: Зеленый/Изумрудный
- Текст: Должность + Название Организации
- Кнопка действия: `[КАРТОЧКА]` (Белая/Серая)
  - Открывает просмотр

### 6.3. Модальные окна

**Создание контакта:**
- Обязательно наличие выпадающего списка (Select) с организациями
- После сохранения окно закрывается, а шапка чата мгновенно обновляется (становится "Известным") без перезагрузки страницы F5

**Карточка клиента:**
- Демонстрация полей: ФИО, Компания, VIP-статус
- Наличие кнопки-заглушки "Открыть в ERP"
