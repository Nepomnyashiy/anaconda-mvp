# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ: ANACONDA CORE (v4.0)

**Принцип:** Единое досье контакта + Агрегация каналов.
**Стек:** Python 3.11 (FastAPI), SQLite/PG, Vue.js 3, Polling Workers.

---

## 1. БАЗА ДАННЫХ (Источник правды)

Мы модифицируем схему так, чтобы `Contact` был единой точкой входа для сообщений.

### 1.1. Таблица `organizations` (Сущность: Компания)

*Справочник юридических лиц.*

* `id` (PK)
* `name` (String, Unique) — "ПАО Газпром".
* `is_vip` (Bool) — Визуальный маркер (Корона).

### 1.2. Таблица `contacts` (Сущность: Человек)

*Агрегатор личностей. Один человек может иметь несколько каналов связи.*

* `id` (PK)
* `org_id` (FK) — Привязка к компании.
* `name` (String) — "Иванов Иван".
* `position` (String) — "Главный инженер".
* **Каналы связи (Identity Columns):**
* `email` (String, Index, Nullable) — "ivanov@gazprom.ru"
* `telegram_id` (String, Index, Nullable) — "12345678"
* `phone` (String, Index, Nullable) — "+7999..." (задел на будущее)



### 1.3. Таблица `messages` (Сущность: История)

*Хранит переписку, привязанную к каналу, но мы будем вытаскивать её через Контакт.*

* `id` (PK)
* `source` (Enum: 'telegram', 'email') — Откуда пришло/куда ушло.
* `sender_id` (String) — Технический ID (email или chat_id).
* `is_outbound` (Bool) — **True** (Мы ответили), **False** (Клиент написал).
* `is_read` (Bool) — Статус прочтения.
* `text` (Text) — Тело сообщения.
* `attachment_path` (String) — Ссылка на файл (для MVP храним локально).
* `created_at` (DateTime).

## 2. BACKEND (FastAPI Logic)

### 2.1. Входящие сообщения (Workers)

Логика "Привязки на лету" при получении сообщения (Telegram/Email):

1. **Получить сообщение** (через Polling).
2. **Поиск Контакта:** Ищем в таблице `contacts` совпадение по `telegram_id` или `email`.
3. **Сохранение:**
* Записываем сообщение в `messages`.
* Поле `sender_id` заполняем исходным ID.


4. **Результат:** Если контакт найден, сообщение автоматически "прилипнет" к нему в интерфейсе. Если нет — попадет в папку "Неразобранное".

### 2.2. API: `GET /api/hub_structure` (Главный экран)

Возвращает полное дерево для левого меню.

```json
{
  "unsorted": [
    // Список sender_id, которых нет в таблице contacts
    { "sender_id": "tg_555", "source": "telegram", "preview": "Сколько стоит?", "time": "14:15" }
  ],
  "organizations": [
    {
      "id": 1, "name": "ПАО Газпром",
      "contacts": [
        {
          "id": 10, "name": "Иванов Иван", "position": "Директор",
          "channels": ["telegram", "email"], // Иконки, доступные для этого контакта
          "unread_count": 2
        }
      ]
    }
  ]
}

```

### 2.3. API: `GET /api/history/{contact_id}` (Чат с человеком)

Агрегирует историю из **всех** каналов этого человека.

**SQL-логика:**

```sql
SELECT * FROM messages
WHERE sender_id = :contact_email
   OR sender_id = :contact_telegram_id
ORDER BY created_at ASC;

```

### 2.4. API: `POST /api/send` (Отправка)

Единый метод отправки.

* **Вход:**
* `contact_id` (кому, берем из базы).
* `channel` ('telegram' или 'email' — менеджер выбирает, куда ответить).
* `text` (текст).
* `file` (опционально).


* **Логика:**
1. Найти `Contact` по ID.
2. Если канал Telegram -> взять `contact.telegram_id`.
3. Если канал Email -> взять `contact.email`.
4. Отправить во внешний мир.
5. Сохранить в БД с `is_outbound=True`.



### 2.5. API: `POST /api/link_contact` (Магия)

Превращает "Неразобранное" в "Сотрудника".

* **Вход:** `{ "sender_id": "tg_555", "name": "Петр", "org_id": 1 }`
* **Действие:** Создает запись в `contacts` с `telegram_id="tg_555"` и привязкой к Организации.
* **Эффект:** Чат мгновенно исчезает из "Неразобранного" и появляется внутри Организации.

## 3. FRONTEND (Vue.js + Tailwind)

Интерфейс должен быть максимально чистым.

### 3.1. Левая панель (Картотека)

* **Блок "Неразобранное" (Inbox):**
* Красные карточки.
* Отображается только технический ID (или имя из профиля мессенджера).


* **Блок "Компании" (Аккордеон):**
* Серые папки с названиями компаний.
* Внутри — список **Людей**.
* Рядом с именем человека — набор мелких иконок (Telegram/Email), показывающих, какие каналы у него подключены.



### 3.2. Центральная панель (Лента сообщений)

* **Header:**
* Крупно: ФИО Сотрудника.
* Мелко: Должность | Компания.
* Кнопка `[Редактировать]` (карандаш) — открывает модалку для добавления второго email или телефона.


* **Body (Сообщения):**
* Сообщения из Telegram — с синей полоской.
* Сообщения из Email — с желтой/красной полоской.
* Исходящие — справа, зеленые.


* **Footer (Ввод):**
* **Селектор канала:** Выпадающее меню или табы над полем ввода: `[Ответить в Telegram] | [Ответить на Email]`. Активно только то, что есть у контакта.
* Скрепка 📎 для файлов.



### 3.3. Модалка "Обработка Лида"

Появляется, когда открываем чат из "Неразобранного".

* Заголовок: "Кто это?"
* Поля: "Имя", "Должность".
* Выбор компании: "Существующая (Список)" или "Новая (+)".
* Кнопка: "Сохранить".
